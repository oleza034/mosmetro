# KODA.md — контекст проекта MosMetro

## Обзор проекта

**Цель проекта MosMetro** — подсчёт статистики поездок на городском транспорте Москвы и оценка целесообразности приобретения **Единого билета на 365 дней** при фактической (подсчитанной) интенсивности поездок.

Проект состоит из двух частей, связанных файлом `history.json`:

- **parser** (`google_parser.py`) — чтение данных из открытого на экране телефона приложения Moscow Metro (`ru.mosmetro.metro`): парсинг экрана полной статистики (истории) поездок через Appium.
- **cost_counter** (`cost_counter.py`) — модуль подсчёта статистики по действующим на момент создания проекта тарифам. Оценивает, выгоднее ли кошелёк/90 минут или абонемент «Единый 365», с учётом «бюджета неудобства» (допуск ±3000 ₽ в год).

Проект не использует официальный API: источник данных — интерфейс приложения на реальном Android-устройстве.

**Детали частей:**

1. **`google_parser.py`** — UI-парсер истории поездок.
   - Подключается к Android-устройству через **Appium** (UiAutomator2, сервер по адресу `http://localhost:4723`).
   - Пролистывает экран «История» свайпами с фиксацией пальца (гашение инерции), собирает текстовые элементы с координатами (`bounds`).
   - Группирует элементы в «карточки» операций по вертикальным зазорам (`CARD_GAP_PX = 80`), распознаёт плашки дат («сегодня», «вчера», «24 октября») с обработкой перехода через год.
   - Определяет тип станции МЦК по пиксельному совпадению иконки с эталоном `mcc_template.png` (шаблон создаётся автоматически ровно один раз со станции «Локомотив», перезапись запрещена).
   - Сохраняет уникальные записи `[дата-время, название, цена]` в `history.json` (дедупликация по времени).
   - Остановки: дата старше 365 дней, либо контент экрана перестал меняться (низ истории), либо лимит 250 скроллов.

2. **`cost_counter.py`** — тарифный симулятор и аналитика.
   - Читает `history.json`, очищает данные (отбрасывает служебные тексты, дубликаты, битые метки времени).
   - Симулирует тарифную модель кошелька: окно 90 минут за 75 ₽, доплата до тарифа 90 минут 37 ₽ (наземный после рельсов и обратно), бесплатные пересадки между разными подтипами рельсового транспорта (метро / МЦК / МЦД), повторный вход на тот же подтип — новое окно.
   - Платные поездки (цена > 0, дальнее МЦД) нейтральны — в сравнении не участвуют.
   - Границы анализа определяет по реальным данным: конец = самая свежая запись, начало ограничено 365 днями и самым свежим «месяцем без поездок» (данные старше считаются недособранными).
   - Выводит месячную разбивку, годовую экстраполяцию и вердикт: что выгоднее с учётом допуска ±3000 ₽ (`TOLERANCE`).
   - Результат — `final_clean_report.csv`.

**Технологии:** Python ≥ 3.12, управление окружением через **uv** (`pyproject.toml` + `uv.lock`, `.venv`). Ключевые библиотеки: `appium-python-client` (+ `selenium`), `opencv-python`, `numpy`, `pandas`, `pillow`. Стандартная библиотека: `json`, `os`, `re`, `time`, `shutil`, `datetime`.

## Сборка и запуск

Полная подготовка рабочего места (Android Studio + ADB, режим разработчика на телефоне, `uv`, Appium, открытие нужного экрана) описана в `README.md`. Краткая сводка:

**Подготовка (однократно / перед каждым прогоном парсинга):**
1. Установлены Android Studio (universal ADB-драйвер + adb SDK), Appium (`npm i -g appium` + драйвер `uiautomator2`).
2. На телефоне включён режим разработчика, разрешены отладка по USB и установка через ADB; телефон подключён по USB и подтверждён запрос «Разрешить отладку с этого компьютера?» (проверка: `adb devices`).
3. Виртуальное окружение проекта: `uv.exe sync`.
4. Запущен сервер Appium командой `appium` (адрес `http://localhost:4723`).
5. На телефоне открыто приложение «Московский транспорт» → **полная статистика (история) поездок**; на экране должна отображаться полная статистика. Приложение НЕ перезапускается скриптом (`noReset`, `dontStopAppOnReset`).

**Запуск:**
```bash
uv.exe run python google_parser.py   # шаг 1: собрать историю → history.json
uv.exe run python cost_counter.py    # шаг 2: анализ → final_clean_report.csv
```

Параметры устройства зашиты в `get_driver()`: udid `86R0226708007114`, путь к `adb.exe` (`C:\Users\zakaz\Downloads\platform-tools\adb.exe`) — при смене телефона или машины править там.

**Тесты:** автоматических тестов в проекте нет. TODO: при изменении логики тарифной симуляции проверять вручную на контрольных срезах `history.json`.

## Правила разработки

- **Язык кода и комментариев:** русский (комментарии, логи, сообщения пользователю — на русском; префиксы `[LOG]`, `[WARN]`).
- **Стиль:** плоские скрипты без классов и фреймворков; функции с аннотациями типов (`-> tuple | None`, PEP 604); `snake_case`; константы верхнего регистра в начале модуля.
- **Парсинг без хрупких зависимостей:** разбор `bounds` намеренно сделан без регулярных выражений; ролевые признаки текста (время `ЧЧ:ММ`, цена с `₽`) важнее позиции элемента.
- **Защита данных:** `history.json` и `mcc_template.png` дополняются, но никогда не перезаписываются; дедупликация записей по метке времени.
- **Временные файлы** (`full_screen_temp.png`, `current_icon_temp.png`) удаляются в блоке `finally` основного цикла.
- **Пороговые константы** (стоимость окна, доплата, цена абонемента, `CARD_GAP_PX`, порог совпадения иконок 0.85) вынесены в константы с комментариями — менять только осознанно.
- **Дублирование логики:** `SERVICE_WORDS` и распознавание транспорта продублированы в обоих скриптах — при правке синхронизируйте оба файла.
- **Данные в git не попадают:** `.gitignore` исключает `*.json`, `*.csv`, `*.xml` — `history.json` существует только локально, не рассчитывайте найти его в клоне репозитория.
