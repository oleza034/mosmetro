# MosMetro

Проект MosMetro предназначен для **подсчёта статистики поездок на городском транспорте Москвы** и оценки целесообразности приобретения **Единого билета на 365 дней** при подсчитанной интенсивности поездок.

Проект состоит из двух частей:

1. **parser** (`google_parser.py`) — чтение данных из открытого на экране телефона приложения «Метро Москвы» (`ru.mosmetro.metro`). Скрипт подключается к телефону через Appium, пролистывает экран полной статистики и сохраняет поездки в `history.json`.
2. **cost_counter** (`cost_counter.py`) — модуль подсчёта статистики по действующим на момент создания приложения тарифам («Кошелёк», окно 90 минут, доплата за пересадку наземный ↔ рельсы). Модуль оценивает целесообразность приобретения Единого билета на 365 дней и выводит вердикт с учётом «бюджета неудобства» (±3000 ₽ в год).

Результат работы cost_counter — отчёт в консоли и файл `final_clean_report.csv`.

## 1. Подготовка компьютера

### 1.1. Android Studio, ADB-драйвер и adb SDK

1. Установите [Android Studio](https://developer.android.com/studio) (в комплекте идёт SDK Manager).
2. Установите **универсальный ADB-драйвер** устройства (Universal ADB Driver) — особенно для телефонов Xiaomi/Huawei/etc., либо драйвер из SDK для Android-устройств Google.
3. В SDK Manager (или отдельно — Command Line Tools) установите **Android SDK Platform-Tools** — это и есть `adb.exe`.
4. Добавьте каталог `platform-tools` в `PATH` либо запомните полный путь к `adb.exe` (он также прописан в `google_parser.py` → `get_driver()` → `adbExecPath`).

### 1.2. Python-окружение через uv

1. Установите [uv](https://docs.astral.sh/uv/) (`pip install uv` или установщик для Windows).
2. В каталоге проекта выполните:

   ```bash
   uv.exe sync
   ```

   Виртуальное окружение `.venv` и все зависимости (`appium-python-client`, `selenium`, `opencv-python`, `numpy`, `pandas`, `pillow`) будут установлены из `uv.lock`.

### 1.3. Appium

```bash
npm install -g appium
appium driver install uiautomator2
```

## 2. Подготовка телефона

1. Включите **режим разработчика**: Настройки → О телефоне → многократно нажмите «Номер сборки» (7 раз).
2. В появившемся меню «Для разработчиков» включите:
   - **Отладка по USB** (USB debugging);
   - **Установка через USB** / разрешить установку приложений по ADB (на MIUI — «USB-установка», может потребоваться аккаунт Mi);
   - на некоторых прошивках — «Отладка по USB (настройки безопасности)».
3. Подключите телефон к компьютеру по USB кабелю.
4. **При первом подключении на телефоне появится запрос «Разрешить отладку по USB с этого компьютера?» — подтвердите его** (желательно с галочкой «Всегда разрешать с этого компьютера»).

## 3. Проверка перед работой

Перед каждым прогоном парсинга убедитесь:

1. **Телефон виден по ADB:**

   ```bash
   adb devices
   ```

   Устройство должно быть в статусе `device` (не `unauthorized` — иначе не подтверждён запрос отладки на телефоне).

2. **Запущен Appium** (в отдельном окне терминала):

   ```bash
   appium
   ```

   Сервер должен слушать `http://localhost:4723`.

3. **На телефоне открыто приложение «Метро Москвы»**, и в нём открыта **полная статистика** (история поездок). Убедитесь, что на экране отображается полная статистика — скрипт работает «как пользователь» и сам навигацию не строит.

## 4. Запуск

```bash
# Шаг 1 — сбор истории поездок с экрана телефона → history.json
uv.exe run python google_parser.py

# Шаг 2 — подсчёт статистики и вердикт по Единому 365 → final_clean_report.csv
uv.exe run python cost_counter.py
```

Шаг 2 можно запускать в любое время — он работает только с файлом `history.json` и телефон не требует.

## 5. Примечания

- UDID устройства и путь к `adb.exe` зашиты в `google_parser.py` (функция `get_driver()`). При смене телефона или компьютера обновите значения `udid` и `adbExecPath`.
- `history.json` пополняется без дубликатов (дедупликация по дате/времени поездки) — можно запускать парсер регулярно, подтягивая только новые поездки.
- Приложение во время парсинга не перезапускается и не закрывается; не трогайте телефон, пока скрипт пролистывает историю.
- Шаблоны и временные файлы: `mcc_template.png` — эталон иконки МЦК (создаётся автоматически один раз, не удаляйте), `*_temp.*` — временные скриншоты, удаляются автоматически.
